### 🧭 How I work
<!-- TODO: delete any line that isn't true for you. These only work if you can back each with a story. -->

- **Ship the simple version first.** A brute-force version that works beats an elegant design that doesn't exist yet. I optimize once real usage shows me where it hurts.
- **Understand the user before the code.** Most bugs I've prevented were really misunderstood requirements.
- **Own it after deploy.** Logs, alerts, and the fix, not just the pull request.
- **Choose boring tech on purpose.** Novelty is a cost; I spend it only where it buys something.
- **Leave a trail.** A good README and a short note on *why* a decision was made save the next person a day.
